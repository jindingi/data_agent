# Data Agent 设计原则与 AI 实施规范

更新：2026-11-07。适用：Electron 桌面 Renderer、React、shadcn/ui（Radix）、Tailwind CSS、Streamdown。本文是后续设计与评审的约束，不是功能已完成的声明。具体缺陷、实施顺序和验收见 [UX 修复计划](ux-remediation-plan.md)；产品边界见 [产品说明](mvp-plan.md)。

## 2. 核心判断标准

用户应能顺利完成：开始提问、知道 Agent 正在做什么、处理必要交互、读完结果、继续追问。每个新增常驻元素必须能说明它帮助其中哪一步。

- 优先级：数据与操作安全 → 可完成任务 → 上下文稳定 → 可发现与可理解 → 视觉精度。
- 减少功能范围可以接受；不可接受报告读不完、误建会话、按钮含义不明或切换后丢草稿。
- 工作台不保证分析正确，不把程序结束、文件存在或 UI 绿点表达成业务分析正确。
- “本地”须准确：原文件路径与计算在本机，必要内容仍可能发送给模型提供方。不用 LOCAL 暗示本地模型或完全离线。

## 3. 信息与术语

- 侧栏叫“会话”；workspace 仅指磁盘工作区；运行指一次执行；文件预览不推断文件是否是正确报告。
- 常驻信息限于当前会话/文件/模型、执行状态、需处理事项及高频操作。
- 删除 LOCAL、产品口号、英文装饰副标题和常驻正常健康状态；不为“专业感”补徽标、卡片、统计数字或装饰图标。
- 隐私和策略在首次配置及设置中可找到；真实审批展示具体操作，避免重复占用每轮输入区。
- 默认隐藏 UUID、版本哈希、内部目录结构；详情保留完整路径和复制入口。版本使用可读时间/序号。
- 状态准确：执行完成、已停止、等待批准、文件不可预览分别表达，不使用一个泛化“成功”覆盖所有情况。

## 4. 布局与阅读

- 桌面顶栏只保留一层主要导航，保留窗口按钮和拖动区；交互控件必须排除 drag 区域。
- 聊天与预览各有受约束的独立滚动区域。flex/grid 链路明确 min-height/min-width，不以隐藏溢出掩盖内容不可达。
- 宽屏允许拖拽调宽并提供专注阅读；窄窗口切换阅读模式，不强塞三栏。改变布局保留文件、版本和阅读位置。
- 悬浮元素不能遮住正文、输入区或键盘焦点。长表格/代码局部横滚，应用整体不横向溢出。
- 回答保持连续阅读；内部字符切片不得变成用户必须操作的正文分页。原始工具日志可独立分页。
- 新消息、新产物不抢走正在阅读的内容。用户主动关闭预览后，不因后续文件事件反复打开。
- 产物图像保持原色，不因深色主题反色；图片可进入放大查看并返回原阅读位置。

以下是本项目后续实现的起始预算，不是外部标准或现状描述；如需调整必须记录具体窗口和验收证据：

| 项目          | 目标                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| 顶栏          | 44–52 CSS px，兼顾 macOS 窗口控件                                                    |
| 预览并排      | 占侧栏之外可用宽度约 40%–50%；聊天至少 420px、预览至少 420px；不足则进入覆盖阅读模式 |
| 预览工具区    | 正常状态不超过 120px，正文优先；异常提示不得截断内容                                 |
| 阅读正文      | 14–15px，行高约 1.6–1.8；专注阅读正文最大宽度约 760–860px                            |
| 控件/次要文字 | 常规控件 12–13px；辅助文字 11–12px；不靠 8–10px 字体制造精致感                       |
| 标题与间距    | h1/h2/h3 形成实际级差；间距使用少量统一刻度，不逐处堆魔法数字                        |

## 5. 草稿、附件与提交

- “新会话”进入首页草稿；首次发送被工作台接收才创建正式会话。选择文件/目录、取消选择和重复回首页均不得产生正式空会话。
- 草稿包含文本、待提交路径和待选工作区；切换会话保留各自草稿。具体恢复范围和提交失败恢复见修复计划。
- 输入框只显示待提交附件；接收后移到该条消息的附件记录，同时进入会话文件列表。清空输入框附件不解除会话文件关联。
- 已关联资料后续可用，无需重新附加；本次新增与历史关联要区分。解除关联不删除原文件，旧消息保留提交时的路径元数据，不做文件内容版本快照。
- 提交前校验失败保留草稿；接收后模型失败保留正式会话。重复请求使用稳定提交身份，不只依赖禁用按钮。
- Enter 发送、Shift+Enter 换行、兼容 ⌘ Enter；输入法确认和长按不能误发。回首页不停止其他会话。

## 6. 控件契约与无障碍

- 使用原生语义元素和完整 Radix 交互；Renderer 不通过 Node/Electron API 绕过 preload。
- 纯图标按钮同时有可访问名称和可见 Tooltip。Tooltip 描述动作及已有快捷键，hover 和键盘 focus 均可出现，Escape 可关闭。推荐统一悬停延迟 400ms；不要为每处单独设计时序。
- aria-label 不能替代 Tooltip；浏览器 title 也不能作为统一可发现性方案。已完整显示的普通文字不必重复弹提示。
- 图标可保持 14–16px，但独立点击目标至少 32×32px；主要工具栏使用 36×36px。分隔线使用适合拖动的命中范围及键盘等价操作。
- 下拉箭头必须打开菜单或选择器。打开设置、创建会话、切换归档使用准确动作，不隐藏在误导性的箭头里。
- 视觉上像链接的内容应能通过受控流程打开；不支持的内容使用明确普通文本，禁止“下划线但点不了”。
- Tabs、菜单、对话框要有完整键盘行为；关闭弹窗后焦点返回触发入口，若入口已删除则回到合理的下一处。
- 删除使用危险操作样式及明确对象/影响说明；审批保留具体操作、路径和一次性范围，不用 Tooltip 隐藏重要后果。
- disabled 有可理解的原因。不能依赖禁用元素接收 hover 才给解释，必要说明放在相邻文本或可聚焦容器。

## 7. 反馈与状态

- 字段错误在字段附近；设置提交错误在该弹窗内；执行失败在对应轮次内。不要把错误扔到弹窗背后的全局横幅。
- 保存/导出/连接明确进行中，避免重复操作；失败保留输入并提供可执行恢复动作。
- “已复制”短暂显示并可被辅助技术读取；“已导出”提供打开目标位置入口。Toast 不是长错误和审批的唯一载体。
- 空态提供当前下一步，区分没有会话、没有搜索结果、无附件、暂未生成文件和加载失败。
- 运行状态允许用户观察和停止；不伪造百分比。同一轮的思考与工具调用合并为一个执行过程区：运行时展开摘要行，结束时自动收起，允许用户手动查看全部详情；正文、失败摘要和待审批交互不能被折叠隐藏。手动查看过程暂停跟随末尾，自动折叠不得把键盘焦点留在隐藏内容中。
- 模型入口支持搜索/提供方分组/配置状态；模型能力与本客户端实际开放能力分别说明。

## 8. 视觉与组件实现

- 优先复用 components/ui 中的组件；组合 Tooltip、Tabs、Menu、Dialog、Resizable 等前先检查 components.json、已安装原语与对应版本文档，不凭最新示例更换基础库。
- 语义颜色、字号、间距、圆角、阴影集中维护。深浅主题共享结构与行为；颜色不得是状态唯一载体。
- 正文采用清晰中性颜色，强调色用于主要动作/选中；危险、等待、失败有各自语义。逐控件核对 focus/hover/selected/disabled，而非只截首页。
- 优先系统字体与现有 Lucide；不新增远程字体、营销插画、纹理、动效背景或仅装饰的依赖。
- 动画服务于状态变化，尊重 reduced motion；不延迟输入、停止和审批操作。
- 不在既有重复 CSS 后无限追加覆盖。修改时归并相关布局规则，避免同一面板在多个媒体查询里相互抵消。

## 9. AI 开发者的设计检查步骤

1. 读相关产品约束、当前组件与样式，列出当前任务、状态转换和受影响区域；说明事实、推断与待验证项。
2. 定义主要动作、阅读/滚动归属、焦点恢复和失败路径，再选组件；每个新增常驻元素说明用途。
3. 用合成 fixture 覆盖空态、加载、失败、待审批、长内容和并发；先建立能捕获目标缺陷的检查。
4. 授权实施后运行真实 Electron/CDP：鼠标、键盘、状态/存储与几何断言结合；mock 仅替换模型响应或选择器结果，不替换业务链路。
5. 查看深浅两套主题截图及必要的真实交互，记录可发现性、信息密度和视觉层级的人工/AI 评审；截图存在不等于已复核。
6. 报告本次验证范围与未验证内容，每阶段通过后提交。程序回归、UX 视觉评审、数据分析 Judge 分别记录，不混为同一“通过”。

新增设计原则时优先补充可观察的用户行为与验收，不写“更高级”“更有质感”等无法执行的要求。
