# 右侧工作区文件浏览器改造方案

状态：待实施。本次只形成方案，不改变现有产品行为。后续实施按本文验收，并同步产品说明、技术设计、使用指南和测试指南。

## 1. 目标与交互

右侧直接展示当前会话 workspace 的实际目录内容，不再混合“关联输入文件”和“已登记产物”。用户无需理解文件关联或产物登记状态，就能找到工作区中的脚本、报告、图表和数据。

- 面板标题为“工作区”，保留“文件 / 预览”两个 tab、宽度调整与专注阅读。
- “文件”展示目录树，目录按需展开，文件点击后进入预览。文件夹优先、同类按名称排序；不默认展开整棵树。
- 工具栏保留刷新、在 Finder 中显示工作区、展开/收起面板；纯图标按钮提供 Tooltip 与可访问名称。
- 删除输入文件分组及“解除关联”按钮；不新增另一套“会话引用文件”列表。
- 外部 CSV 仍直接引用原路径，不复制进 workspace。对应消息保留已提交附件信息；工作区外的 CSV 不出现在右侧。CSV 原本位于 workspace 时，像普通目录文件一样展示，不因它是输入而隐藏。
- 新会话首页没有正式 workspace：显示“发送第一条消息后创建工作区”。已创建但空的目录显示“工作区暂无文件”。目录不可访问、文件被移除、读取失败分别显示，不冒充空目录。
- 文件内容正在变化时提示刷新；预览中不自动跳到另一个文件。刷新保留目录展开状态、选中文件和可保持的阅读位置，文件消失则显示明确状态。
- 首版不增加文件编辑、重命名、移动、删除、终端、搜索或操作系统默认程序直接执行入口。不支持的预览类型提供“在 Finder 中显示”，由用户自行打开。

右侧表示的是磁盘当前状态，不表示文件一定由 Agent 创建、本轮已交付或分析正确。面板刷新不得修改执行成功/失败状态。

## 2. 当前实现及真正需要改动的范围

| 当前模块                                   | 现状                                                                     | 修改方向                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| `ArtifactPanel`                            | 合并 `inputs: FileReference[]` 与 `artifacts.list`，依赖登记文件 ID 预览 | 改为工作区目录数据驱动，拆开目录列表与通用预览职责                       |
| `SessionService.files/addFiles/removeFile` | 维护 `file_refs`，也承担输入文件预览与定位                               | 取消可变关联集合和产品入口；历史记录仅作兼容保护，不再用于列表或提交准入 |
| `RuntimeService`                           | prompt、steer、follow-up 都合并历史 `file_refs` 检查文件存在性和累计大小 | 只对本次输入携带的附件做校验；历史路径不阻止普通追问                     |
| `ArtifactService`                          | 任务收束后扫描登记、hash 检查、预览与导出                                | 不再作为右侧目录列表来源；本轮保留既有交付/清理账本和历史产物兼容能力    |
| `PolicyService` / `DeletionService`        | 使用输入路径保护原始 CSV，防止默写或误删                                 | 保留来源保护，不能随“解除关联”一起删除                                   |
| 原生 JSONL                                 | `data_agent.input_submitted.paths` 与用户输入保留历史附件                | 原样保留，不回写旧消息、不重复注入旧路径                                 |

这不是把 `artifacts.list` 换个名字。现有登记只覆盖任务收束后扫描到的候选产物，无法直接满足“手动放入文件后刷新可见”“任务执行期间浏览”等需求。

## 3. 列目录与刷新：无需全量递归登记

新增 Main `WorkspaceFileService`，Renderer 使用 `features/workspace/` 下的目录视图。可复用现有 `Report`、`SourcePreview`、`ZoomImage` 和尺寸控制，不复制一套渲染器或主题。

建议契约（名称在实施时按项目命名统一）：

| 命令                | 请求参数                                | 行为                                                                                           |
| ------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `workspace.list`    | sessionId、可选 directoryId、showHidden | 从会话记录确定根目录，仅列当前层；返回 Main 生成的条目 ID、名称、类型、大小/修改时间及截断状态 |
| `workspace.preview` | sessionId、entryId                      | 校验身份与路径后有界读取，返回现有预览合同所需内容                                             |
| `workspace.copy`    | sessionId、entryId                      | Main 重新校验并复制当前可展示文本；明确截断时仅复制预览内容                                    |
| `workspace.reveal`  | sessionId、可选 entryId                 | 校验后在 Finder 显示对应条目或根目录                                                           |

条目 ID 是 Main 生成的有界内存索引，不是产物 ID、不写入 SQLite。它不是授权凭证：每次读取仍验证会话归属、根目录与当前文件身份。刷新时同路径条目尽量保持稳定 ID；应用重启或索引失效后重新列目录获取 ID，不能把失效 ID 解释成任意路径。Renderer 不传绝对路径发起读取。

刷新触发：

1. 打开面板或切换会话时读取根目录；展开目录时读取该层。
2. 用户点击刷新时重读根目录与当前展开的目录，不扫描未展开子树。
3. 当前会话工具执行结束时合并刷新请求，建议防抖 300 ms；run 终态补一次刷新。只监听相关事件，不随每个流式 delta 请求目录。
4. 隐藏面板只标记待刷新，不持续读取；再次打开时更新。其他会话事件不得刷新或覆盖当前视图。

首版不引入 fs.watch、全目录实时监听或固定间隔轮询。工具长时间运行中若需查看新文件，用户可以手动刷新；Finder 外部修改也可手动刷新，不承诺即时同步。

使用异步目录迭代，单层最多读取/返回 2,000 条；超出时明确“仅显示已读取的部分条目”，提供 Finder 入口，不假装完整列表。不为列表读取文件内容、计算 hash 或累计整个目录体积。内存索引需设上限并能通过重新加载恢复。以上是本方案的实现上限，不改变既有工具执行资源配额。

## 4. 预览与访问边界

- Markdown 渲染、PNG 展示与源码/CSV 原始文本预览沿用现有组件和大小限制。CSV 不解析、不生成表格；HTML/SVG 等源文件只按文本展示，不执行。
- 目录浏览不依赖 `artifacts` 登记。新建但未登记的 `analysis.py`、手动放入的 `notes.md` 均可预览；查看它们不自动授予清理或导出资格。
- 默认隐藏点文件，提供“显示隐藏文件”选项；敏感路径规则在两种模式下都生效。符号链接可标识为不支持，首版不跟随；FIFO、socket、设备文件不读取。
- 根目录来自 `sessions.workspace`，校验实际路径；拒绝根目录被替换为链接、父目录逃逸、其他会话条目 ID、敏感应用状态和凭证路径。
- 预览前后校验实际路径、普通文件类型与文件身份，读取有界；列出后文件被删除、替换或持续写入时返回明确错误。不得为了展示“当前文件”关闭既有路径检查。
- Markdown 相对图片只在当前 workspace 内经受控 ID/资源解析读取；禁止借图片路径、链接或 URL scheme 访问任意外部文件。外链继续遵守现有策略。
- 长 Markdown、长代码和表格仍有独立滚动；不把所有文件一次性读入 Renderer，不把工具日志复制到文件浏览器里。

## 5. 附件与原始文件保护

### 本次提交的校验

建议将用户可理解的上限明确为：每个文件及**每条输入本次附加文件的合计**均不超过 100,000,000 bytes。prompt、steer、follow-up 使用同一规则；选择/拖拽与最终接收都校验本次路径，最终接收失败保留草稿。

不附带文件的普通追问，不再重新 stat 历史附件；旧文件缺失或历史累计超过 100 MB 不阻止发送。队列中附件内容不冻结；接收后原文件消失，实际读取失败交由工具和 Agent 处理。不同轮次实际使用的数据量可能超过 100 MB，工作台不根据自然语言推测 Agent 选用了哪些历史文件；进程与输出资源限制仍独立执行。

这是对旧“当前关联集合累计校验”的产品口径调整，实施时须同步文档和测试，不能只改 UI 文案。

### 取消关联状态，但不取消来源保护

本轮不新增替代 `file_refs` 的可变关联表。新输入路径继续写入原生 JSONL；已有 `run_files` 用于记录已接收输入的来源元数据与清理保护，覆盖普通输入和运行中的 steer/follow-up。

- 每条新输入接收时，将其路径以 `(run_id,path)` 去重写入 `run_files`；与输入接收账本保持事务及恢复语义。不能先投递 Host、之后才补来源保护。
- 运行时保护集合可以从该会话历次 `run_files` 与旧 `file_refs` 的路径合并得到，但**不对历史路径检查存在性、不将历史大小加进本次上传总量**。新附件只追加到保护集合，不能使旧原文件失去保护。
- `ArtifactService` 排除源文件与 `DeletionService` 防误删沿用该来源集合；已提交的 CSV 恰好在 workspace 内时仍可浏览，但不能因此变成可自动清理的生成产物。
- `run_files` 是元数据/保护账本，不是新聊天历史；不能用于决定 Agent“应使用哪些数据”，也不作为前缀重建依据。

## 6. 旧数据与现有产物能力的兼容

采用非破坏性退役，不在这次 UI 改造中直接 DROP `file_refs`：

1. 停止新产品流程向 `file_refs` 写入；移除 `files.pick/add/remove` 及 preload 的旧 addFiles 入口，更新 fixture，不保留一个隐藏的可变关联 API。
2. 旧 `file_refs` 暂时只读，用于保护升级前选择过的原始文件；不展示、不重新校验、不注入模型。已有删除会话事务继续按原有依赖顺序清理对应元数据。
3. 暂不从这些旧行伪造消息或 run。部分旧记录可能只有选择行为，没有可靠对应的提交；直接搬进 run_files 会制造不存在的运行归属。彻底删表需另做无损迁移，不作为本轮完成的前提。
4. `artifacts/output_versions` 保留用于已登记交付、已有导出和删除清理，**不得把 workspace 浏览列表直接作为删除目标**。目录读取不调用 publish，不新增清理目标。既有登记规则本轮不扩大。
5. 现有导出入口明确称“导出已登记产物”，不假装导出整个当前 workspace；没有登记产物时禁用并说明。目录中未登记文件可用 Finder 访问。完整目录导出后置。
6. 旧 run/version 历史目录和记录不删除、不搬移。保留低频“历史产物”入口查看旧登记内容；若历史目录也位于 workspace，普通目录浏览照常展示实际文件。历史产物入口不挤占默认目录视图。

这次改变文件浏览的数据源，不重做产物归属算法、备份/版本管理或删除会话规则。后续若要废弃产物登记，应另行设计导出与清理语义，不能从“能显示目录”推导出“可以递归删除目录”。

## 7. 实施顺序与自动验收

实施前检查最新提交、工作树与 `--affected --dry-run`；以下是提交边界，不新增 Pn 测试命令。每步验收通过后创建本地 commit，正常经过 Husky，不自动 push。

| 步骤                  | 开发目标                                                    | 可自动验证的成功标准                                                                                                                                                                     |
| --------------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A：目录服务与受控预览 | 新增 WorkspaceFileService、contracts、IPC；复用预览基础设施 | 无运行/无产物登记时能列根与子目录；手动新文件可见；文件/目录排序稳定；超量列表明确截断；不新增 artifacts 行；错误 ID、跨会话、链接、根替换、敏感路径及文件替换均拒绝                     |
| B：右侧目录 UI        | 将目录浏览与历史产物兼容 UI 分离，移除 inputs/removeInput   | 后台 CDP 展开目录、预览 md/py/csv/png、刷新增删文件；保留选中与滚动；运行中手动刷新可见新文件；结束事件刷新；关闭不自动重开；双会话迟到结果不串面板；无解除关联按钮                      |
| C：附件与来源保护     | 本次输入校验、run_files 补齐、退役旧关联 API                | 旧文件移除后普通追问可接受；本次缺失/超量仍拒绝且保留草稿；同批多文件总量超限拒绝；跨轮合法附件累计超限不阻塞；steer/follow-up 持久化来源；workspace 内原 CSV 写入仍审批、会话清理仍保留 |
| D：兼容与交付         | 旧库、导出、删除、文档与最终回归                            | 升级保留旧 JSONL 和所有文件；旧 file_refs 不变且只作保护；历史产物可打开/导出；目录浏览不改变删除候选；当前提示词及逐次请求前缀保持稳定；完整普通回归和静态门禁通过                      |

用例组织：新增 `tests/features/workspace/` 并在 `tests/catalog.json` 注册 `workspace.listing`、`workspace.access`、`workspace.browser`。修改既有 composer 的 input-references/file-boundaries/import/submission、preview.files、artifacts、sessions.deletion 与并发/生命周期用例；保留仍成立的负例，不因去掉关联而删掉原文件保护检查。

重点 fixture：

- 空目录、多层目录、中文/空格/长文件名、隐藏文件、超 2,000 条的单层目录。
- workspace 内的已上传 CSV、未登记的手动文件、已登记报告、旧历史目录同时存在。
- 外部上传 CSV 只出现在消息附件，右侧不展示；历史原文件缺失但普通追问可发送。
- 读前替换链接、目录被移动、文件写入期间预览、其他会话 ID、伪造条目 ID。
- 3 种窗口尺寸 × 深浅主题，目录/预览独立滚动、正文末尾、局部横滚、Tooltip、键盘焦点与关闭后恢复；查看真实截图，不以按钮存在当作体验通过。
- 脚本/重放 HTTP 模型验证工具循环、插话、后续提问、新附件与重启恢复的序列化前缀；不重发或改写历史附件。

测试使用官方 runner 的隔离构建、独立数据和后台隐藏窗口；不访问真实业务目录，不覆盖用户应用。先定向 `--feature workspace` 及受影响 feature，再跑 `pnpm quality` 和普通 `pnpm test`。本次不要求真实模型或分析准确性 Judge；程序只验证目录、交互、持久化和边界。若实施改变打包资源或运行时入口，再补对应 .app 用例，不把旧打包通过当作新证据。

## 8. 完成线

用户可以在右侧浏览、刷新并预览当前 workspace 的实际文件；无需理解或操作“关联”。旧附件不会无故阻止追问，原文件仍受保护，历史上下文不变，导出/删除没有因扩大可见文件范围而扩大操作范围。所有改动和迁移的自动回归通过后才算完成。
