# HTML 交互报告实现计划

更新日期：2026-11-08。状态：**功能已实施，验收收尾中**。已在 `codex/interactive-html-reports` 接入资源、skill、配置与隔离预览，未将真实模型失败计为完成。本文保留原始阶段目标，当前产品合同已归入 [产品说明](mvp-plan.md)、[技术设计](technical-design.md)、[SQLite 设计](sqlite-design.md) 与 [使用说明](usage.md)；实际测试入口见 [测试指南](testing-guide.md)。

## 1. 已确认的方向

1. 新增内置 `interactive-report` skill；现有 `data-analysis` 继续用于 Markdown + 静态图片。
2. 内置 Apache ECharts，Agent 直接编写 HTML/CSS/JavaScript 和 ECharts 配置，使用现有 Python 做数据准备。
3. **不固定报告布局、章节、图表数量或组件组合。** Agent 根据数据分析意图决定表现形式；长篇解释、单图探索、多视图比较都应成立。
4. **不建设报告 DSL、必填业务 schema、组件生成器或强制模板。** 不规定所有报告都包含 KPI、筛选栏或明细表。
5. 技术示例按需读取；装配辅助仅处理资源封装和序列化，不决定展示内容，是否内置在验证后决定，不作为首版前置依赖。

这里的“自由编写”仍遵守文件访问、资源预算和浏览器权限边界，不代表 HTML 可访问 Node、工作台 IPC 或任意本地文件。生成内容与分析方法由 Agent 负责，应用保证访问与展示流程，不增加运行时业务正确性判定器。

## 2. 目标体验与范围

用户要求交互 HTML 时，Agent 在同一会话 workspace 生成报告及必要的分析源文件。用户从现有文件面板选择 HTML，可交互阅读、切换源码、刷新、展开阅读、另存单个 HTML。已有 Markdown、PNG 和源码预览继续使用原路径。

默认交付自包含 `report.html`：图表库只内嵌一次，CSS、报告脚本、交互需要的数据及图片资源包含在文件内；文件名可由用户另定。生成期间可保留分开的 JS/CSS/JSON/Python 源文件，不要求 Agent 用一个巨大 write 调用一次写完。另存后的报告不依赖应用安装目录、原 CSV 路径或网络 CDN。

首版应用内执行合同为单文件 HTML；本地相对资源、外部脚本、模块依赖和网络数据源不属于执行合同。不满足合同的文件仍可查看源码或另存，加载失败要如实提示，不自动启动服务器、不自动安装包或放宽访问策略。该约束限制分发形式，不限制报告布局。

报告是生成时的数据快照，浏览器只操作已嵌入的数据。原文件变化、额外分析和 Python 重新计算通过后续提问完成；不把 JS 回调接回 Agent 或模型。已有 workspace、500 MiB 累计限额、会话删除保留 workspace 等规则不变。

首版不包含实时数据库、HTML 内调用 Python、地图在线瓦片、第三方包安装、React/Vite 报告工程、服务端应用、通用 BI/电子表格系统、目录级报告导出。生成报告不要求新的 Agent 工具或系统 Node。

## 4. ECharts 与 skill 资源

### 4.1 内置方式

- 在依赖准备阶段选择并锁定一个确切 ECharts 版本，已锁定 ECharts 6.1.0 的普通浏览器脚本；不使用 CDN、latest 或生成时下载。锁定文件包含浏览器脚本、LICENSE 与 NOTICE 哈希，开发/打包使用相同字节。
- 从锁定依赖提取发布字节，构建时校验来源、文件哈希和 LICENSE/适用 NOTICE，输出到独立构建/运行时资源目录；版本、校验规则、许可处理代码入 Git，可重建的分发文件留构建产物。
- ECharts 供报告使用，不要求把它打进工作台主 Renderer。先用完整基础分发降低组件缺失风险，有实际体积证据后再由应用构建阶段裁剪，不由 Agent 按任务打包。
- 使用现有资源准备、验证与隔离打包流程扩展 JS 资源检查，不建立运行时 npm 下载器。运行时资源清单与报告文件索引是不同概念；不新增报告 manifest、artifacts 表或 output_versions。
- skill 提供稳定的资源相对路径和简短用法。Agent 用 Python 读取库字节并内联，不把 minified 库读进模型上下文；导出的 HTML 保留相关版权与许可告知。

建议的资源职责如下，目录名以最终实现为准：

```text
resources/skills/interactive-report/
  SKILL.md                       # 交付约束、资源位置、按需资料入口
  references/echarts.md           # 当前内置版本的简短 API 示例
  references/offline-html.md      # 单文件装配、数据转义和离线限制
```

不增加 `templates/report.html` 或固定布局 CSS。示例只说明图表初始化、事件、数据更新、resize/dispose 等局部技术用法，不提供必须复制的整页报告。Agent 自己编写筛选状态及数据处理代码；ECharts 事件联动不等于自动完成业务交叉过滤。

### 4.2 不可变资源与恢复

现有 revision 的正文、描述、路径、指纹和提示词保持不变。新增版本化资源必须满足：

1. 在既有 `agent_config_revisions.snapshot` 合同中增加有版本的资源描述；新合同独立解析，旧快照沿用原解析与指纹算法，不能给旧对象补默认字段后重新计算摘要。
2. 小型文本资源随新快照保存内容及哈希，可像 SKILL.md 一样恢复；大型 ECharts 字节使用受信内容寻址缓存，快照保存确切版本、哈希、资源路径与许可引用，不把库正文存入每份 SQLite 快照或聊天历史。
3. 资源集合摘要包含排序后的相对路径与内容哈希，生成固定目录；新资源包不覆盖旧目录。先写临时文件、校验并物化，再事务提交配置绑定。文件与 SQLite 不视为原子事务，失败留下的无引用缓存不影响旧绑定。
4. 应用升级保留已绑定的资源缓存；首版不自动回收这些缓存。缺失资源仅可从相同哈希的受信安装资源或已有缓存恢复，不下载、不用新版本替代。无法恢复时明确报配置资源缺失，不重建旧上下文。
5. 已生成的自包含 HTML 继续可查看，与生成资源是否存在分离。重装/备份恢复后旧资源不可用，不能因此隐藏或删除旧报告。
6. 缓存检查拒绝符号链接、越界和哈希不符；Agent 对资源的可检测写入/删除仍拒绝。保留现有“尽力策略”的表述，不宣称资源路径是 OS 沙箱。

不新增 SQLite 表；新 JSON 合同、旧数据恢复与应用降级限制需要写入 [SQLite 设计](sqlite-design.md)。新版本须读取旧快照；旧应用版本不保证能读取新配置，应说明备份/回退边界，不能删掉新快照伪造兼容。

## 5. 新旧 skill 的选择与上下文

- 普通分析仍默认 Markdown + PNG；明确要求 HTML、可交互、筛选或联动时选择 interactive-report；同时要求两种格式时才交付两种。分析意图与交付格式存在重要歧义时使用已有澄清工具。
- interactive-report 自含必要的分析方法与口径提醒，不依赖先执行 data-analysis；禁用旧 skill 后仍能独立完成交互报告。禁用新 skill 时不宣称相关内置指导仍启用；skill 开关不作为禁止 bash 生成 HTML 的安全权限。
- 新安装的默认配置启用两项 skill，但一般任务仍走原格式；已有安装不静默修改已保存默认修订，新 skill 在设置中显式启用并保存后用于新会话。已有、运行中、排队会话不热插入 skill。
- 新会话的提示词选择说明使用新 promptVersion；旧 promptVersion 保留字节一致的组装/恢复行为。新资源路径、skill 描述及声明顺序在会话创建时固定，不在每次请求前更新。
- 技术资料由 Agent 按需 read，结果正常追加并持久化；不把整套文档注入系统提示词，不反复删除/替换已读资料，不注入动态资源状态或预算。
- 直接检查提供方最终序列化请求：工具循环、预算变化、steer/follow-up、跨轮共享 workspace、新附件、重启恢复。压缩单独标识允许的前缀重建边界；录制不兼容要重新审阅，不能放宽 replay 匹配。

skill 应指导 Agent 将 CSV 字符串作为数据处理，正确嵌入 JSON、处理 `</script>`、空值/日期/大整数，避免把数据值拼成 HTML 或可执行代码。是否聚合/抽样以及采用何种布局由任务决定；不能固定要求全量数据入 HTML，也不能把统计口径固化到装配工具。

## 6. 独立 HTML 查看器

### 6.1 宿主与访问合同

首选验证 `WebContentsView + 独立非持久化 session + 受控报告协议`。阶段一必须验证原生 view 与现有 React 面板/弹窗的布局、遮挡和焦点；失败时先修订本节，不默认退回主 Renderer 执行 HTML，也不扩张为任意网页浏览器。

主 UI 只发送 sessionId/entryId 和查看器操作。Main 使用现有工作区访问规则验证归属、根路径、普通文件、链接、大小及读取前后文件身份；完成读取后签发绑定窗口/报告/生命周期的短期查看能力。协议只提供该次已验证的 HTML 字节，不把 workspace 映射成静态服务器，不接受任意磁盘路径。退出查看后撤销能力；旧请求不能复活已关闭报告。

起始执行上限定为 **单 HTML 32 MiB**，包括库和内嵌资源，超限只提供源码有界预览及另存；不截断后执行。此值是待验证的工程预算，不是已证明的性能保证。全局最多保留一个活动报告 view 及一份已验证 HTML 内存副本；读取不能建立无界历史缓存。若阶段一测量需改阈值，先调整本计划与测试合同。

### 6.2 执行权限

- 独立 view 保持 nodeIntegration:false、contextIsolation:true、sandbox:true、webSecurity:true，不加载应用 preload、不注册业务桥；宿主 IPC 继续校验可信窗口和主 frame，报告 view 无权调用。
- CSP 由 Main 的报告响应施加。允许该 HTML 的内联脚本与样式来支持自由报告，不允许 eval/Function、外部脚本、网络连接、frame/object、表单提交或 worker。图片/字体仅支持所需的内嵌 data 资源，具体指令在阶段一以 ECharts 实跑确定。
- 如果采用允许内联的策略，只作用于隔离报告文档，不能改变工作台主 Renderer 的 CSP。执行任意报告脚本本就是能力范围；CSP 不是判定生成代码可信的机制。
- 在独立 session 同时实施请求限制和权限 check/request 拒绝，阻止 HTTP(S)、WebSocket、file 和其他未授权 scheme；阻止跨文档导航、子 frame 导航、弹窗、设备/文件系统权限、报告触发的下载。普通页内锚点须可用。外链首版不自动打开，不为报告增加 shell.openExternal 桥。
- HTML 另存由宿主已有文件操作完成；首版不承诺 ECharts 工具栏的图片下载或报告内任意下载按钮可用。外部浏览器打开导出件不受工作台 session 策略管理，不宣传为同一隔离环境。
- JS 错误、资源被拦截、加载失败、renderer 崩溃/无响应有明确状态；关闭/重新打开由宿主操作，不依赖报告脚本响应。错误摘要有界，不把报告正文或用户数据作为无限日志输出。

### 6.3 阅读与生命周期

HTML 与源码切换复用工作区面板，不新增另一套主题状态或文件索引。应用工具栏继续使用语义 tokens、Radix/Lucide；报告自己的布局、颜色和主题由 Agent 决定，不注入固定模板、不强制反色。

同一报告的调宽、展开、面板暂时隐藏、源码切换和宿主弹窗不应重载页面；需正确隐藏原生 view，避免覆盖设置、审批或菜单。保留内页滚动和筛选。切换文件/会话会销毁旧 view，返回时重新加载，首版不承诺跨文件/重启保存任意 JS 状态；此行为不能伪装成恢复了筛选。

文件变化不自动重载正在阅读的页面。刷新是显式动作：重新校验并读取文件，重置报告内交互；刷新时文件被替换/仍在写入则提示重试。关闭主窗口可销毁 view，但不得中止后台 Agent 任务；会话删除、窗口退出与失败重试均释放 view/session 引用、短期能力和内存字节。

## 7. 分阶段实施

以下为原定阶段门槛，按依赖顺序推进。资源/配置、skill 和查看器已实现；真实生成与完整门禁需按实际结果分别验收。阶段完成须检查实际结果、运行对应门禁并创建本地 commit，不 push；文档计划提交不计任何功能阶段完成。

| 阶段                     | 工作与交付                                                                                                                                                   | 完成门槛                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 一：技术验证与合同冻结   | 锁定 ECharts 候选；合成单文件离线报告；用现有隐藏 Electron/CDP harness 验证独立 view、CSP、窗口布局/遮挡、错误/卡死关闭；测量 HTML 大小、加载/筛选延迟和内存 | 确认版本、实际 CSP、32 MiB 阈值及预览方式；至少三类不同表现形式成立，无固定布局依赖；技术证据不得冒充产品完成     |
| 二：资源与配置版本       | 接入 ECharts 构建/许可校验、可信 skill 清单、附属资源快照与缓存、新旧配置合同及恢复路径                                                                      | 开发/.app 资源可定位；断网可读取；旧配置摘要与路径不变；缺失/篡改/升级/数据库提交失败可恢复或明确拒绝，无静默替换 |
| 三：新 skill 与生成链路  | 编写 interactive-report 指导和局部示例，设置启停与新会话路由，使用通用工具生成自包含报告                                                                     | 开关/单独启用/双格式意图正确；有确定性交付与完整请求前缀回归；不新增模板、DSL 或分析专用工具                      |
| 四：正式预览与工作区接入 | Main 受控读取/协议/view 管理，shared/preload 窄合同，面板 HTML/源码/刷新/另存，失败与销毁路径                                                                | 真实 CDP 验证交互、焦点、阅读、跨会话隔离、网络/权限拒绝、文件竞态；旧 Markdown/PNG/源码回归通过                  |
| 五：真实交付与收尾       | 真实 DeepSeek 生成不同意图的报告，隔离 .app 的离线/迁移验收，性能与视觉评审，正式文档归并                                                                    | 程序门禁、视觉评审、Agent 效果评价分别记录；必需项无 skip/未测；完成相应回归后提交                                |

阶段一使用手写合成报告识别技术风险，不调用真实模型；可复用验证纳入正式测试，截图/产物/一次性探针留忽略目录。阶段三不能仅凭存在 report.html 宣称交互有效，最终交互交付在阶段四、五验证。

装配辅助的决策点在阶段三末：检查三类不同意图的生成过程。如果反复出现相同的库内联/JSON 转义错误，可增加只负责封装的 Python 标准库辅助脚本；接口接受自由 HTML/数据片段，不规定组件、章节或图表 schema，并纳入资源快照和回归。若通用工具已足够则不增加脚本。不把“先造一套脚手架”作为阶段完成条件。

| `reports.delivery`                                            | scripted，E2E               | 真实通用工具写文件并装配、发现 HTML、另存后字节/资源完整；旧 Markdown 交付仍可用；不把模型 fixture 当真实生成质量           |
| `preview.html-access-unit` / `preview.html-lifecycle-unit`    | none，unit/integration      | 完整读取上限、路径/会话/窗口校验、令牌撤销、文件替换/符号链接/读取竞态、无截断执行                                          |
| `preview.html-isolation`                                      | none，真实 Electron E2E     | IPC、任意文件、跨会话、外连/重定向/资源 URL/WebSocket、弹窗/导航/frame、设备权限、下载、异常及死循环关闭                    |
| `preview.html`                                                | none/scripted，E2E          | 自由布局、点击/缩放/输入、共享筛选和重置、空结果；深浅宿主主题、三种窗口尺寸、独立滚动、焦点/浮层、显式刷新、隐藏/切换/退出 |
| `packaging.interactive-reports`                               | none/scripted，packaged E2E | 锁定库/许可齐全、资源断网可用、移动 .app、工作区 HTML 另存后离线重开、HTML 不依赖原始 CSV/应用路径                          |
| `reports.live-interactive`                                    | live，E2E                   | 真实模型分别交付三类报告；实际打开并操作；失败/审批如实记录，不能凭文件存在或手工替写结果通过                               |
| `performance.interactive-reports`                             | none，E2E                   | 固定合成数据、一个图与多个图、聚合与较大点数、接近上限/超限文件；测 HTML 字节、首个可交互时刻、筛选延迟、峰值内存及关闭回收 |

三个真实生成意图至少包含：

1. 趋势解释为主的叙事报告，只需局部时间交互，不要求指标卡或明细表。
2. 两个群体的分布比较，以区间选择或图例切换探索差异，不要求统一仪表板结构。
3. 多维业务比较，筛选后多个图/指标同步变化；需要表格与否由任务决定。

固定合成 fixture 的交互状态可以用确定性断言检查；真实模型的分析数值、分母、关联口径、结论与自由布局适配由独立 Judge 评审，不把它做成生产文件展示前的审核。视觉评审读取实际截图并操作，不以截图存在代替通过。先记录生成成功率和失败原因，不预设“任意意图保证成功”。

执行要求：

- 日常 `pnpm quality`，用 `pnpm test -- --affected --dry-run` 检查覆盖理由；每阶段选择已注册的相关功能用例。新增 ID 注册前不把它当现有可运行命令。
- 所有程序用例使用隔离数据根和隐藏窗口；构建/打包必须通过正式 runner 的独立上下文，不写用户正在运行的 out/release，不为测试关闭用户实例。
- 普通回归无真实密钥；新增 live 测试显式 `--live`，沿用 live-key、合成数据、预算和审批规则；新 skill 不给测试自动批准未知命令的权限。
- 最终至少完成受影响的普通回归、新增 HTML/资源用例、指定 packaged/live 用例。若按完整发布交付，执行 `pnpm test -- --suite release --live`，不能用定向测试冒充完整 release 通过。
- 导出浏览器兼容性先以目标 Chromium 验收；macOS Safari 另做离线打开/交互检查并独立报告，未测不宣称通用浏览器兼容。测试浏览器不得关闭 webSecurity。
