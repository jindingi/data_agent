# 工作台 UX 修复计划

更新：2026-11-07。状态：**本轮修复与 UX5 正式验收已完成**。完整 P7 为 68/68 通过；实际覆盖及视觉复核见文末。

依据用户截图、反馈和当前源码评审制定；采用 [设计原则](design-principles.md)。原 [P0–P7 开发计划](development-plan.md) 与 [实施进度](implementation-status.md) 保留历史事实，本计划补充交付后发现的体验缺口，不能用旧门禁通过来证明这些缺陷不存在。产品和进程边界仍以 [产品说明](mvp-plan.md)、[技术设计](technical-design.md) 为准。

## 1. 修复目标与范围

让用户能够开始一段对话、附加文件、观察执行、完整阅读结果并继续工作；减少没有用途的常驻信息，让状态与操作含义一致。本次不换品牌、不重新造 Agent、不添加 CSV 解析器，也不保证分析结论正确。

已确定的行为：

- 新会话进入草稿首页，首次发送被工作台接收才创建正式会话。
- CSV 仅引用原路径；输入框展示待提交文件，会话文件列表展示已关联资料，两者分开。
- 预览可调宽、可完整滚动、可专注阅读；长回答连续展示。
- 纯图标按钮有 hover/focus 提示；下拉箭头与实际动作匹配；降低顶栏及辅助信息占用。
- 深浅主题、Enter 发送/Shift+Enter 换行、输入法、多轮/插话、并发、审批等现有能力必须保留。

不在本轮扩展：ACP、数据内容版本管理、CSV 数据表预览、用户自定义 skills、公开发布、多平台、业务准确性验证器。尺寸是可测试的设计起点，实施时可依据实际窗口调优，需记录理由而非临时逐处覆写 CSS。

## 3. 目标交互与状态约定

### 3.1 工作台结构

- 左侧为“会话”，提供新会话、搜索与会话状态；不要把会话集合叫工作空间。
- 顶部合并重复区域，保留 macOS 控件、拖动区、当前上下文和少量高频操作；低频会话操作放菜单，删除不得与主操作同等强调。
- 中间为连续对话与紧凑自增高输入框。执行状态靠近当前轮次；待审批保持明显、可操作。
- 右侧为“文件”与“预览”。预览由文件身份驱动，不凭扩展名或模型声明给出正确性背书。选择 Markdown/PNG 可打开预览；其他格式明确显示可执行的打开/导出操作。
- 并排预览默认占侧栏以外宽度约 40%–50%，聊天/预览各至少 420px；不足时采用覆盖式专注阅读，退出返回原上下文。分隔线可拖拽和键盘调整，记住合理宽度并在窗口缩小时约束范围。
- 预览工具区合并文件名、版本与操作，正常状态高度不超过 120px；版本使用日期/序号，哈希、完整路径移到详情。文件变化只提示，不覆盖用户当前选择。

### 3.2 草稿和正式会话

首次提交路径为：草稿 → 校验与接收 → 正式会话/排队或运行。校验包括模型配置、路径存在与大小、提交身份；不解析 CSV 内容。

- 首页草稿有独立身份，不预先创建正式 SQLite 会话、JSONL 或 workspace。未发送前选择自定义工作区只保存选择意图，首次接收再初始化。
- 新会话按钮导航到唯一首页草稿，不无限新增草稿。已有草稿不得无提示清空；切换已有会话分别保留输入。
- 首页草稿的文本、路径及工作区选择可在独立本地草稿存储中恢复，不含凭证、不放入正式 sessions 表或 pi 会话树；重载/重启后不自动发送。实施时在技术设计中明确 schema 与清理规则。
- Main 使用稳定 inputId 保证重复提交幂等；跨 SQLite、JSONL、目录创建不存在天然原子事务，必须设计失败补偿/启动对账。接收前失败不留下正式空会话；接收后模型调用失败则保留会话、用户消息和可恢复错误。
- “已接收”不等于模型完成：排队也算接收。切换页面不影响任务，关闭窗口/退出语义沿用原方案。

### 3.3 附件生命周期

| 状态           | 展示与行为                                                          |
| -------------- | ------------------------------------------------------------------- |
| 待提交         | 输入框显示路径附件，允许移除；选择器取消不改变已有草稿              |
| 已接收         | 本次附件进入对应用户消息与会话资料；输入框清除本次已提交部分        |
| 发送前失败     | 文本和附件保留，可修改后重试                                        |
| 接收后模型失败 | 已提交消息/资料保留，不重新伪装成未发送附件                         |
| 后续提问       | 已关联资料仍可用，不要求反复附加；新增资料随具体 inputId 传给 Agent |
| 解除关联       | 影响后续可用资料，不删除原文件；历史消息保留当时路径元数据          |

提交期间继续输入或附加新文件时，只清除已接收的快照，不能清掉用户后来编辑的内容。steer/follow-up 同样携带本次路径；停止导致输入未被消费时，恢复文本与附件。并发会话不得串附件。

保留每文件和单次选用总量均不超过 100,000,000 bytes 的边界；不能仅校验输入框中新加的几枚附件而绕过总量。路径去重、同名不同路径、缺失文件需有明确反馈。Agent 使用原路径；不加入文件内容快照、编码探测或替换监测。

### 3.4 连续阅读

- 向上滚动按需加载历史，保留视口中可见消息与偏移；不使用覆盖正文的分页工具条。
- 接近底部时跟随新增消息；用户上翻后保持位置，只显示小型“回到最新”箭头和必要的新消息提示。回到底部后消失；箭头有 Tooltip 和可访问名称。
- 长回答和报告按 Markdown 语义连续展示，跨阈值的代码、表格不能被切坏。工具原始日志可以单独分页；控制 DOM/内存不等于让用户手动翻答案的字符页。
- 预览关闭后不被文件事件反复打开；阅读旧版本时保持版本、文件、滚动位置，用户主动选择再更新。

## 4. 阶段、开发目标与验收

顺序：UX0 → UX1 → UX2 → UX3 → UX4 → UX5。每阶段完成后提交实现、必要测试及文档；失败只能标 WIP，不得标完成。可以提前做不依赖前序的组件准备，但不能跳过回归。

_*下列 UX-* 是待实现的用例合同，不是现有 runner 已支持的 case ID。_* 实施时先注册测试入口与必需清单，缺失用例、skip/todo、零用例不能算通过。不能现在运行假想命令后把“未找到测试”解释为成功。

### UX0 — 建立可复现的体验基线与安全验证环境

开发目标：让后续改动可对照验证，且不打断用户当前使用中的工作台。

实施内容：

1. 准备合成会话：长历史、长 Markdown、宽表格、长路径、图表、多版本、等待审批、失败和双会话；不使用用户原始数据。
2. 在真实 Electron/CDP 记录用户问题的操作步骤、窗口尺寸及前后截图；区分截图已证实、源码推断、尚未复现。对展开按钮单独验证点击、最终宽度、正文可达性。
3. 检查 runner 的构建/打包副作用；需要时补充独立打包输出及配套验证路径。测试数据隔离不代表 out/release 隔离。
4. 将下列验收用例逐步接入正式测试目录/清单；保留旧门禁，修改过时的 UX 假设时记录原因，不删除有效生命周期覆盖。

成功标准：

| 计划用例    | 可自动判断的结果                                                                             |
| ----------- | -------------------------------------------------------------------------------------------- |
| UX-ENV      | 测试业务目录与 userData 独立；构建/打包输出不覆盖在用实例；结束后只回收测试进程              |
| UX-BASELINE | fixture 可重复生成；已复现缺陷对应断言在旧实现失败，记录实际失败项，不以预期失败计为功能通过 |
| UX-MATRIX   | 能固定 940×650、1280×800、1440×900 CSS 视口及两种主题；截图和用例结果可关联                  |

提交：`test(ux0): establish isolated UX regression fixtures`。仅建立基线不宣称修复完成。

### UX1 — 阅读区域与信息布局

开发目标：用户能读到报告末尾，并在需要时给内容足够空间。

涉及：App.tsx、ArtifactPanel.tsx、globals.css、必要的公共布局组件。修复高度约束和滚动归属，加入可调宽/专注阅读，压缩重复顶栏与工具区，移除装饰性文案；统一 Markdown 基础排版。保留审批及运行入口。

| 计划用例      | 成功标准                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------- |
| UX-READ-END   | 使用真实 wheel/PageDown 到长报告尾部，尾部标记可见；聊天与预览分别滚动；不能仅靠读取 DOM 文本判通过 |
| UX-RESIZE     | 拖动及键盘均改变预览实际宽度；达到最小值后不挤出窗口；扩大/退出保留文件和版本                       |
| UX-RESPONSIVE | 三种视口无整体横向溢出；窄窗口阅读模式可退出；窗口尺寸变化后正文、输入及关闭按钮均可达              |
| UX-DENSITY    | 顶部主要导航总高度符合设计预算；正常预览工具区 ≤120px；LOCAL、口号、常驻正常健康提示已移除          |
| UX-TYPOGRAPHY | 标题级差可测；表格/代码局部横滚且不扩大页面；PNG 不反色；两主题的焦点/正文可辨认                    |

除自动断言外查看两主题截图，核对内容优先级与拥挤程度。提交：`fix(ux1): make workspace and previews readable`。

### UX2 — 草稿会话、提交与附件状态

开发目标：没有空会话污染，用户能理解文件是否已提交，失败/并发不丢输入。

涉及：sessions/runtime hooks、App、Main Session/Runtime 服务、shared contracts、输入身份/恢复逻辑和可能的数据迁移。先写状态转换与接收边界，再实现；维护 pi 原生 JSONL，不从 UI 文本重建会话。

| 计划用例         | 成功标准                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| UX-DRAFT         | 连续点击新会话、选择/取消文件与目录，正式会话数、JSONL 数及 workspace 数均不增加；首页草稿仍可恢复        |
| UX-FIRST-SEND    | 第一条有效提交后仅有一个正式会话；双击、重发相同 inputId、延迟响应不会重复建会话/消息/任务                |
| UX-ACCEPTANCE    | 注入接收前校验/初始化失败不留下空会话；接收后模型失败仍有对应会话和用户消息；崩溃恢复无孤立正式记录       |
| UX-ATTACHMENTS   | 接收后已提交附件离开输入框、出现在消息及资料区；未接收则保留；提交中新增文字/附件不被旧响应清除           |
| UX-FILE-BOUNDS   | 同名不同路径正确区分；同路径去重；缺失/超限反馈可见；100 MB 文件与总量边界保留，原文件从未被复制/删除     |
| UX-INPUT-CONTEXT | 普通输入、steer、follow-up 的新路径随正确 inputId 到达 Agent；未消费输入停止后恢复；会话 A/B 无串扰       |
| UX-DRAFT-RESTORE | 切换会话、Renderer 重载、应用重启保留对应草稿与路径；不自动发起执行；Enter/Shift+Enter/⌘ Enter/IME 无回归 |

更新旧 E2E 中“点新会话即存在”的假设，真正走首次提交；底层存储测试可显式造 fixture，但不能用测试桥替代此 UI 验收。提交：`fix(ux2): separate drafts submissions and file references`。

### UX3 — 历史、长内容与产物上下文

开发目标：阅读持续稳定，流式事件不抢焦点或替用户换文件。

涉及：Transcript、PagedText、ToolLogViewer、ArtifactPanel、运行事件到 UI 的状态合并。

| 计划用例              | 成功标准                                                                                            |
| --------------------- | --------------------------------------------------------------------------------------------------- |
| UX-HISTORY            | 超过当前历史窗口的会话能连续向上加载；加载前后锚点偏移误差 ≤8 CSS px；无固定浮条遮正文              |
| UX-FOLLOW             | 阅读旧消息时新增 text/tool 事件不改变锚点；回到最新按钮仅在离底部时出现，点击后到底部并恢复跟随     |
| UX-LONG-MARKDOWN      | 超过旧 8192 字符切片及多个阈值的回答，跨界表格/围栏完整；流式尾部、结束正文、完整复制均可达且无截断 |
| UX-ARTIFACT-STABILITY | 关闭预览后新增产物不强开；阅读旧文件/版本时更新不换选中项；切换阅读模式后恢复位置                   |
| UX-VIEWERS            | 长文件名可获取完整名称；图片可放大并返回；非预览格式有明确操作；不存在或被删除的产物显示可恢复状态  |
| UX-LONG-SESSION       | 长会话沿用原 P6 性能门禁，并记录 DOM/内存与加载耗时；不因连续展示而一次挂载全部原始工具日志         |

提交：`fix(ux3): preserve reading context across streaming updates`。

### UX4 — 控件语义、反馈与键盘行为

开发目标：用户知道按钮做什么、操作是否生效，错误出现在能处理的位置。

涉及：公共 IconButton/Tooltip、Dialog/Tabs/Menu、ModelSettings、InteractionCard、安全外链展示和操作反馈。采用匹配锁定版本的 Radix/shadcn 组件；增加依赖须说明必要性，不整体更换 UI 基础。

| 计划用例    | 成功标准                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| UX-TOOLTIPS | 枚举纯图标操作，有可访问名称；hover 与 focus 显示正确动作/快捷键，Escape 关闭；状态改变后名称同步；点击目标至少32px |
| UX-KEYBOARD | Tab 可达主要操作；Tabs 方向键与选中面板关联；对话框困住焦点、正确关闭名称、关闭后恢复触发位置；splitter 支持键盘    |
| UX-ACTIONS  | 每个下拉箭头打开对应菜单；会话归档、工作区查看、模型选择无歧义；删除有危险样式和明确对象                            |
| UX-FEEDBACK | 设置错误在弹窗内；提交期间明确 busy 且防重复；失败保留输入；复制/导出有反馈及正确目标位置入口                       |
| UX-MODELS   | 模型可搜索、按提供方区分、看见配置状态；切换不重置无关草稿；不把模型能力误当工作台已支持的输入能力                  |
| UX-LINKS    | 允许的外链经 Main 受控打开；不执行危险 scheme，不开启任意本地文件访问；显示为链接的内容真实可操作                   |
| UX-STATES   | 空态、搜索无结果、加载、失败、停止、待审批均有正确可执行提示；无假进度、无“分析已验证正确”表述                      |

提交：`fix(ux4): clarify controls feedback and keyboard interactions`。

### UX5 — 整体验收与文档收束

开发目标：所有修复在实际开发启动和交付应用中成立，且未破坏 Agent 外围工作流。

1. 执行 UX0–UX4 全部必需用例及受影响单元/集成测试；真实 `pnpm dev`、构建后 Electron、独立打包 `.app` 各验证关键流程，不把 build 模式当成 Vite 开发模式。
2. 最终完整执行原 P7 门禁与发布资源校验，沿用实际 DeepSeek 配置、预算及审批规则。测试前确保输出安全隔离；资源校验器指向本次包及匹配构建，不能校验另一份旧包。
3. 录入长历史阅读、附件提交、并发/审批/停止、窗口关闭重开、重启恢复；三种尺寸与两主题进行视觉检查。系统窗口拖动等 CDP 不能充分覆盖的行为单独做本机交互检查，如实列明。
