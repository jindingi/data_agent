# 会话存储与工作区管理简化方案

状态：已完成。2026-11-07，A–D 已实施并通过验收。当前实现与阶段证据见 [实施进度](implementation-status.md)。

本文是本轮存储清理的实施依据；[工作区浏览方案](workspace-browser-plan.md) 负责目录与预览交互细节。[技术设计](technical-design.md)、[产品说明](mvp-plan.md) 和 [使用说明](usage.md) 目前描述已实现行为，实施时同步更新，不把计划冒充现状。

## 1. 决策与范围

- 删除会话仅移除会话记录和应用内部数据，workspace 及其中所有文件始终保留，用户自行通过 Finder 删除。删除前停止该会话并等待工具退出，不影响其他会话。
- 本轮直接删除 `tool_logs`、`output_versions`，不采用只读退役、兼容视图或后续再删的方案。不保留历史产物版本入口或版本导出逻辑。
- 右侧展示实际 workspace 目录；取消文件关联、产物登记、发布和版本概念。随之删除 `artifacts`，预览和单文件另存不需要持久化目录索引。
- `runs` 的当前执行状态归入 `sessions`；三个输入投递表合一；会话配置改为引用不可变修订；去掉无实际恢复用途的审批数据库记录。
- 不创建另一套日志 manifest、产物清单文件或自建聊天历史来替代被删除的表。会话内容继续以 pi 原生 JSONL 为准。
- 保留工具执行策略、原文件保护、资源限额、输入可靠投递、配置快照和上下文前缀稳定性。这些不依赖产物版本功能。

本方案包含两项明确的功能收敛：原“导出一版产物”改为“另存当前选中文件”；旧版本在 UI 中不再作为版本展示，其实际目录和文件不搬移、不删除。批量目录导出不在本轮增加。

## 2. 数据归属和目标表

| 数据                                                               | 唯一职责归属                                          |
| ------------------------------------------------------------------ | ----------------------------------------------------- |
| 消息、思考、工具调用/结果、轮次用量、已提交附件身份                | 原生 session JSONL；SQLite 只保留投递确认和必要索引   |
| 工作区文件内容与目录                                               | 磁盘；Main 按需列目录和有界读取                       |
| 工具进程的有界完整输出                                             | 磁盘日志文件；不存 SQLite 元数据，不增加 sidecar 索引 |
| 客户端设置、会话目录、当前执行状态、配置修订、待投递输入、来源保护 | SQLite                                                |
| 正在等待的审批/澄清、运行许可、进程句柄                            | Main 内存；重启失效，不从磁盘恢复授权                 |

目标为以下 6 张应用表（不计 SQLite 自身内部表）：

```text
schema_migrations
app_metadata
sessions
agent_config_revisions
input_submissions
session_sources
```

| `run_inputs`             | 合并后删除 | 输入类型、确认状态、entry ID 迁入 input_submissions                  |

### 2.2 sessions：不要混用会话可用性和执行状态

保留 id、title、workspace、session_file、pi_session_id、history_known、archived、创建/更新时间等现有字段。现有 state/error 表示会话历史与目录是否可用，不直接改成运行状态。

新增或明确以下字段组（最终 SQL 名称可按现有约定统一）：

- `creation_pending`：首次发送创建流程尚未完成，替代 conversation_intents。
- `execution_id / execution_epoch / execution_state / execution_started_at / execution_ended_at / execution_error`：最新执行身份和状态。启动模型等 UI 确实使用的最新执行字段一并迁入；不重建历次运行历史。
- `agent_config_revision`：引用不可变配置版本。
- `agent_config_override`：仅保留无法引用现有修订的历史绑定；普通新会话为 NULL。
- 删除仍使用明确的 `deleting` 生命周期状态和错误信息。无需再存 delete_artifacts 开关或删除目标清单。

同一会话只允许一个活跃执行。每次启动生成新 execution ID；状态更新必须同时匹配 session ID、execution ID 和 epoch，旧回调不能覆盖新执行。停止、审批、工具进程和预算仍按执行身份隔离。两个会话并发、FIFO 许可及同会话 pi steer/follow-up 队列保持不变。

重启把未结束执行标记为 interrupted；不恢复运行进程、不重放用户任务、不复活审批。SQLite 不承担持久化任务调度器职责。

### 2.3 input_submissions：一个输入一条投递记录

建议字段：`input_id`、`session_id`、`execution_id`、`kind`、`state`、`entry_id`、`digest`、`pending_text`、`pending_paths`、显式接收顺序。

- 接收输入时同一事务保存投递记录和来源保护路径；之后才向 Host 投递。
- 同 input ID、同摘要返回已接收结果；同 ID 不同内容拒绝，不能重复创建会话或执行。
- 待确认正文是已点击发送但尚未进入原生历史的内容，不是编辑框草稿。后者继续使用现有 Renderer 草稿机制。
- 确认 JSONL 实际用户消息落盘后清空 pending_text/pending_paths，只留轻量身份与摘要，不长期重复保存聊天正文。
- SQLite ACK 落后于 JSONL 时，以实际消息修正；unknown 输入不自动重发。历史执行结束后尚未消费的输入仍可恢复。
- 迁移使用旧接收顺序生成显式序号；不要依赖合表后的隐式 rowid 恰好不变。普通新记录按事务分配顺序。
- execution_id 只是关联标记，不再外键依赖 runs；不因删除 runs 丢掉历史未确认输入。

### 2.4 配置去重和来源保护

配置快照与修订完整匹配时改为引用；revision 为 NULL 或无法严格匹配的旧绑定原样保留 override。版本号、fingerprint、skill 文件路径和正文不变；异常绑定保持不可用，不能绑定最新默认值。配置修订不得因会话删除而被自动清除，skill 快照清理由独立明确策略处理，不纳入本轮。

`session_sources` 仅需会话、规范路径及必要的来源标记，按 `(session_id,path)` 去重。它用于工具执行时保护已接收的原文件，尤其是原文件本来就在 workspace 的情况，不作为 UI 文件目录、当前分析选集、累计大小校验或模型上下文来源。

迁移 file_refs 与经 runs 关联到会话的 run_files；只有选择行为的旧记录标为旧保护来源，不伪造提交/消息/执行归属。新附件在 prompt、steer、follow-up 接收时都追加保护。历史路径无需存在；普通追问不 stat 全部旧来源。按本次输入附带文件校验每文件及合计不超过 100,000,000 bytes，不解析 CSV。

## 3. 工作区、预览与导出

由 Main `WorkspaceFileService` 负责按层列目录、有界预览、复制文本、Finder 定位及单文件另存。Renderer 复用现有 Markdown、图片和源码组件。详细交互与限额见 [工作区浏览方案](workspace-browser-plan.md)。

- 条目 ID 来自 Main 有界内存索引，不写数据库。刷新/重启可重新解析，不承诺历史 artifact ID 继续有效。
- 去掉 ArtifactService 的 openWorkspace/publish/全目录 hash 登记链及运行收束中的发布等待；仍必须等待 Host/工具停止写入和释放资源。
- 工具执行期间的磁盘总量、进程、输出和时间限制继续由原执行监督承担，不能随发布扫描一起删除。
- 去掉版本选择器、历史产物入口、已登记/已发布状态和批量版本导出 API。旧版本目录位于 workspace 内时只是普通目录，其他位置通过 Finder 自行访问，不建立兼容入口。
- “另存文件”使用受控条目 ID 和原生保存对话框。Main 重验源文件与目标，受限流式复制；源文件变化、超限或权限失败时清理本次临时副本并明确报错。不覆盖源文件；覆盖其他目标必须由保存交互确认。无需预先登记或持久化 hash。
- UI 的“执行完成”与文件是否存在分开。程序测试可以按测试任务要求断言 report.md 非空，但产品不依据产物登记判定 Agent 分析正确。

## 4. tool_logs 删除后的日志行为

删除的是 SQLite 工具日志索引及其注册写入，不删除原生 JSONL 中的工具调用/结果。保留已有有界完整输出查看能力，但不再为它建立持久化元数据表。

新日志布局建议为：

```text
logs/{session_id}/{sha256(tool_call_id)}/{execution_id}.log
```

- ProcessRunner 接收可信 session/execution/tool 身份，由 Main 确定路径，删除 LogObserver 的数据库注册链。
- 不把原始 tool call ID 当路径；目录名使用固定 hash，执行 ID 验证格式。每次执行的日志总额仍为 10 MiB，分页仍为 32 KiB，输出截断提示继续显示。
- 查看前用当前活动工具集合或原生历史确认 tool call 属于该会话，再按确定目录有界列出日志文件；不递归搜索整个日志根。日志列表过多时分页，不无限加载。
- Renderer 只传 session/tool 身份和 Main 返回的短期日志条目 ID。读取仍检查根、路径归属、普通文件、符号链接和页大小；不能以可猜测文件名替代授权检查。
- 不持久化另一个 reason/peakRSS/truncated sidecar；执行结果中确有用途的内容仍走既有工具结果，资源监督指标在内存执行路径保留。
- 本轮不迁移旧日志文件、不保留旧 tool_logs 查询兼容。旧会话的 JSONL 工具结果照常可读；无新布局完整日志时明确显示“未保存可读取的完整日志”，不伪造为空输出。
- 旧日志文件保留在原应用日志目录，供用户自行清理；不在数据库迁移时执行全局 rm。此限制需在升级说明中明确，新会话日志可按 session ID 正常清理。

## 5. 删除会话：仅清理应用内部数据

确认弹窗移除产物计数和清理复选框，保留取消、删除按钮，显示 workspace 路径及“在 Finder 中打开”。文案明确：删除对话记录，工作区文件保留；删除后侧栏不再保留该目录入口，对话不能在应用内恢复。

删除顺序：

1. 标记 sessions 为 deleting，阻止新输入并从等待队列移除；重入删除复用同一操作。
2. 停止该会话的 Host/工具，取消审批，等待写者退出。不能为了完成删除杀掉其他会话。
3. 根据可信 session ID 清理原生 JSONL 和新布局下该会话的内部日志目录；不存在视为已完成。只允许应用拥有的固定路径，拒绝重定向，绝不访问 workspace 内文件或用户选择的父目录。日志清理不跟随符号链接，不借用通用任意路径递归删除入口。
4. 内部清理成功后事务删除该会话及其投递/来源记录，删除 Renderer 对应草稿；配置修订保留。
5. 清理失败时保留 deleting/error，提供重试。重启识别 deleting 后继续幂等清理，不重新启动 Agent。

工作区缺失、改名、内容变化或包含原始 CSV，都不阻止删除对话；删除流程无需扫描 workspace。应用内部路径若意外与某个 workspace 重叠，则拒绝文件清理并报错，不能突破“工作区文件保留”承诺。

升级前未完成的删除任务一律停止使用旧 deletion_files：在任何旧删除恢复逻辑执行前切换新实现，废弃旧产物删除授权，只恢复内部记录清理。已被旧版本删除的文件无法恢复，升级不能声称找回。

## 6. 迁移策略

在新应用接收任务、启动 Host 或执行恢复前迁移。不得对正在使用的用户业务库直接运行开发迁移脚本。

1. 使用 SQLite 一致性备份机制备份旧库，包含 WAL 中已提交内容；不用只复制主文件替代一致性备份。备份存应用内部受保护位置，不进入 Git。
2. 新增 migration，不修改已发布迁移。一个事务完成建表/加列、数据映射、依赖重建及删表；foreign key 校验必须通过，不用永久关闭约束绕过问题。
3. 最新执行按 created_at 与稳定旧序号选择；迁移中的活跃执行恢复为 interrupted。迁移全部输入，包括旧执行未确认内容；不能只保留最新 run 的输入。
4. 保留配置绑定、输入摘要、接收顺序和保护路径，逐项校验后按依赖顺序删除旧表。目标库不得保留 tool_logs/output_versions/兼容视图，也不得再有运行时查询它们的分支。
5. 不把文件改动伪装成数据库事务：迁移不重写 JSONL、不搬动或删除 workspace、不迁移旧日志。会话删除的内部文件清理由新删除流程完成。
6. 出错回滚，报告迁移失败，不清空数据库启动、不生成一个替代空会话。对已经迁移的库再次启动不得重复导入或产生新执行。
7. 新 schema 不支持旧二进制直接打开；新版加入 schema 支持范围检查并拒绝未知更高版本，但不能宣称未实现该检查的旧二进制会自动安全拒绝。升级说明明确禁止旧版打开新库。需要回退时使用迁移前备份和匹配版本，明确回退会丢失迁移后新增客户端状态；不能只还原 SQLite 就宣称连同后续 JSONL 写入一起回滚。

## 8. 开发顺序与可自动验收的成功标准

以下是实施 commit 边界，不是长期兼容阶段。所有步骤都属于本轮交付；最终必须删除指定表及其兼容逻辑，不把删表延期到下一轮。

| 阶段                  | 目标                                          | 验收标准                                                                                                                                                           |
| --------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A：目录与文件操作     | 按实际目录浏览、预览、单文件另存，接替产物 UI | 未运行 Agent 也能浏览手动文件；md/png/py/csv 预览；无版本/登记/解除关联入口；文件变化和失效 ID 明确处理；跨会话/链接/敏感路径拒绝；另存不修改源文件                |
| B：删除与日志脱离账本 | 删除 workspace 清理能力，日志改为纯文件访问   | 活跃/排队/空会话删除均可；所有 workspace 文件与目录字节不变；原始外部文件不变；暂停点注入故障后重启可完成内部清理；日志分页/超限/双会话隔离；无日志表读写          |
| C：统一存储迁移       | 合并输入/配置/执行/来源；删除全部废弃表及代码 | 目标 6 表；旧库 fixture 升级、重复启动、迁移回滚；旧配置 fingerprint/skill 内容不变；重复提交幂等；未确认输入不丢失；不存在旧版本兼容读写；旧文件和 JSONL 字节不变 |
| D：完整回归与交付     | 验证真实流程、更新正式说明                    | 两会话并发及第三个排队；steer/follow-up；停止/崩溃/审批；用量重建；新附件与重启上下文前缀；质量门禁和全部普通回归通过                                              |

测试按 feature 维护，新增用例 ID 必须注册到 tests/catalog.json，不能把下列计划名称当成已经可运行的命令：

- `sessions`：存储迁移、投递幂等与恢复、创建失败回收、删除保留工作区、删除内部清理故障恢复。
- `workspace`：目录层级与限额、文件访问、预览/另存、UI 键盘与滚动；替代旧 artifacts 的展示/导出测试。
- `tools`：无 SQLite 索引的完整日志分页与隔离；资源限额、超时、取消和输出截断仍验收。
- `agent-config`：修订引用、特殊旧绑定、不兼容绑定阻塞，禁用工具双侧校验不变。
- `conversation/lifecycle/approvals/usage`：执行身份、双会话 FIFO、旧审批失效、用量及历史投影、实际序列化请求前缀稳定。

重点迁移 fixture 包含：旧版本产物记录、普通/特殊配置绑定、多个历史 run、未消费 steer/follow-up、只有 file_refs 的选择记录、旧日志、待完成产物删除。迁移后直接检查 sqlite_master 和外键；不以 UI 隐藏证明表已删除。

确定性故障覆盖“JSONL 已落盘但 SQLite 未确认”“内部文件已删除但会话行未删除”“旧删除已 prepared 但工作区文件尚未删除”。最后一种必须证明新版绝不再执行旧 workspace 删除目标。

UI 使用官方隔离构建和后台隐藏 CDP，在三种窗口尺寸与深浅主题检查真实截图、滚动、Tooltip、焦点和删除确认。普通回归不读密钥、不请求真实模型；不改模型上下文的存储清理不要求以 live 花费代替确定性验证。上下文相关改动必须按 AGENTS 覆盖最终请求前缀，若涉及缓存读数缺陷再补真实 usage 验证。

每阶段运行相关 feature、静态门禁，检查 diff 后通过正常 Husky 创建本地 commit，不 push。最终运行 pnpm quality、全部普通回归；入口/打包模块受影响时补隔离 .app 验收，不覆盖用户正在使用的 out/release。

## 9. 本轮完成线

数据库只保留 6 张目标应用表。tool_logs、output_versions、artifacts 及旧执行/输入/删除拆表全部从运行时和迁移后的 schema 移除，不另建等价的持久化清单。用户能直接浏览、预览、另存 workspace 文件；删除会话永远不清理 workspace。旧对话内容和配置行为保持，原文件保护、审批、运行隔离、输入恢复及受控读取通过自动回归。
